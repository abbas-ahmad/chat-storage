# Chat Storage

A Spring Boot microservice for storing and managing chat histories generated by RAG (Retrieval-Augmented Generation) chatbot systems. Provides secure, scalable REST APIs for chat sessions and messages, with features like favorites, search, pagination, statistics, rate limiting, and API key authentication.

---

## Features
- **Chat Session Management**: Create, update, rename, mark as favorite, delete, and retrieve chat sessions
- **Message Management**: Add, retrieve, and delete messages within sessions
- **Search & Filtering**: Search sessions by name, filter messages by sender type
- **Pagination**: Efficient pagination for sessions and messages
- **Favorites**: Mark/unmark sessions as favorite
- **Statistics**: Retrieve session statistics
- **Rate Limiting**: Prevent API abuse
- **API Key Security**: All APIs protected by API key (from environment variable)
- **Distributed Tracing**: Full request/response audit logging with trace and span IDs for distributed systems
- **Global Error Handling**: Centralized error responses
- **CORS Configuration**: Secure cross-origin requests
- **Health Checks**: Health endpoints for monitoring
- **Swagger/OpenAPI**: Interactive API documentation
- **Dockerized**: Easy local setup with Docker Compose
- **PgAdmin**: Database management via Docker

## Quick Start (Docker)

### Prerequisites
- Docker and Docker Compose installed on your system
- Git (to clone the repository)

### 1. Clone the Repository
```bash
git clone <repository-url>
cd chat-storage
```

### 2. Run with Docker Compose
```bash
docker-compose up --build
```
This will start:
- **Application**: http://localhost:8080
- **Database**: PostgreSQL on port 5432
- **PgAdmin**: http://localhost:8081 (admin@example.com / admin123)

### 3. Access the Application
- **API Base URL**: http://localhost:8080/v3/api-docs
- **Swagger UI**: http://localhost:8080/swagger-ui/index.html
- **Health Check**: http://localhost:8080/actuator/health
- **PgAdmin**: http://localhost:8081

### 4. Stop the Services
```bash
docker-compose down
```

## Manual Setup (Development)

### Prerequisites
- Java 17 or higher
- Maven 3.6 or higher
- PostgreSQL 15 or higher
- Git

### 1. Database Setup
```bash
# Create PostgreSQL database
createdb chat_db

# Create user (optional, uses default credentials)
psql chat_db
CREATE USER rag_chat_user WITH PASSWORD 'chat_pass';
GRANT ALL PRIVILEGES ON DATABASE rag_chat_db TO rag_chat_user;
```

### 2. Configuration
The application uses the following default configuration (in `application.yaml`):
```yaml
server:
  port: 8080

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/chat_db
    username: chat_user
    password: chat_pass
  jpa:
    hibernate:
      ddl-auto: update
```

### 3. Build and Run
```bash
# Clone the repository
git clone <repository-url>
cd rag-chat-storage-main

# Build the application
mvn clean package

# Run the application
mvn spring-boot:run
# Or run the JAR directly
java -jar target/rag-chat-storage-0.0.1-SNAPSHOT.jar
```

## API Endpoints

### Chat Sessions
| Method | Endpoint                                 | Description                       |
| ------ | ---------------------------------------- | --------------------------------- |
| POST   | `/api/v1/sessions`                       | Create a new chat session         |
| GET    | `/api/v1/sessions`                       | Get all chat sessions (with pagination, search, favorite, stats) |
| GET    | `/api/v1/sessions/{sessionId}`           | Get a specific session            |
| PUT    | `/api/v1/sessions/{sessionId}`           | Rename/update a session           |
| PATCH  | `/api/v1/sessions/{sessionId}/favorite`  | Toggle favorite status            |
| DELETE | `/api/v1/sessions/{sessionId}`           | Delete a session and its messages |

### Chat Messages
| Method | Endpoint                                         | Description                       |
| ------ | ------------------------------------------------ | --------------------------------- |
| POST   | `/api/v1/sessions/{sessionId}/messages`           | Add a message to session          |
| GET    | `/api/v1/sessions/{sessionId}/messages`           | Get messages (pagination, senderType, latest, countOnly) |
| GET    | `/api/v1/sessions/{sessionId}/messages/{messageId}` | Get a specific message            |
| DELETE | `/api/v1/sessions/{sessionId}/messages/{messageId}` | Delete a message                  |

### Other
| Method | Endpoint                  | Description         |
| ------ | ------------------------- | ------------------- |
| GET    | `/actuator/health`        | Health check        |
| GET    | `/swagger-ui/index.html`  | API documentation   |

## Authentication
- All APIs require an API key in the header: `X-API-KEY: <your-api-key>`
- User ID must be provided in header: `X-User-ID: <user-id>`

## Environment Variables

The application can be configured using the following environment variables (see `.env.example`):

| Variable                        | Description                                 | Default Value                |
|----------------------------------|---------------------------------------------|------------------------------|
| PORT                            | Application port                            | 8080                         |
| POSTGRES_DB                     | PostgreSQL database name                    | chatdb                       |
| POSTGRES_USER                   | PostgreSQL username                         | postgres                     |
| POSTGRES_PASSWORD               | PostgreSQL password                         | postgres                     |
| SPRING_DATASOURCE_URL           | JDBC URL for database                       | jdbc:postgresql://localhost:5432/chatdb |
| SPRING_DATASOURCE_USERNAME      | DB username                                 | postgres                     |
| SPRING_DATASOURCE_PASSWORD      | DB password                                 | postgres                     |
| SECURITY_API_KEY                | API key for authentication                  | api_9f3b2e7a-4d6c-4a1f-8b2e-123456789abc |
| RATE_LIMIT_REQUESTS_PER_MINUTE  | Requests allowed per minute per user        | 60                           |

## Distributed Tracing & Audit Logging

This service includes comprehensive request/response logging with distributed tracing support:
- **Trace ID & Span ID**: Automatically generated for every request
- **Audit Logs**: Full request/response logging with sensitive data masking
- **MDC Integration**: Trace context included in all log entries
- **Zipkin Support**: Optional integration for trace visualization

For detailed documentation, see [DISTRIBUTED_TRACING.md](DISTRIBUTED_TRACING.md)
